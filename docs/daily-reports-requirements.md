# 要点定義書 — 日報機能 (`/daily-reports`)

**対象システム:** 社内ポータル v2
**対象ページ:** `http://localhost:3000/daily-reports`
**作成日:** 2026-03-16
**ステータス:** プロトタイプ基準

---

## 1. 概要・目的

スタッフが毎日の業務内容・気づき・引き継ぎ事項を記録し、定型フォーマットの日報テキストをワンクリックで生成・コピーできる機能。

チャットワーク等への貼り付けを想定したフォーマット出力が主目的。

---

## 2. 対象ユーザー

| ユーザー | 操作 |
|---|---|
| 全スタッフ（ログイン済み） | 自分の日報を作成・編集・コピー |
| リーダー以上（将来拡張） | 他メンバーの日報を閲覧 |

---

## 3. 画面構成

### 3-1. 日報一覧画面（メイン）

| 要素 | 内容 |
|---|---|
| ヘッダー | タイトル「日報」＋「今日の日報」ボタン |
| 日報カード | 日付・名前・業務内容・進行中タスク・気づきを表示 |
| アクション | 各カードに「コピー」「編集」ボタン |
| ページング | 5件/ページ、前後ナビ |
| 空状態 | 「日報はまだありません」メッセージ |

### 3-2. 作成・編集モーダル

| フィールド | 種別 | デフォルト | 必須 |
|---|---|---|---|
| 日付 | date input | 当日 | ✅ |
| 名前 | text input | ログインユーザー名 | ✅ |
| ■ 本日行った業務 | textarea | 空 | ✅ |
| ■ 進行中のタスク | textarea | 空 | — |
| ■ 行いたい業務（今後やること） | textarea | 空 | — |
| ■ 引き継ぎ内容 | textarea | 特になし | — |
| ■ 問題点・気づき / 改善案 | textarea | 空 | — |
| ■ 全体共有内容 | textarea | 特になし | — |
| ■ 質問 / サポート依頼 | textarea | 特になし | — |

---

## 4. 機能要件

### 4-1. 日報作成
- 「今日の日報」ボタンで当日日付のモーダルを開く
- 「本日行った業務」が空の場合は保存ボタンを非活性
- 同一ユーザー・同一日付で保存すると**上書き**（1日1件制約）

### 4-2. 日報編集
- 一覧の「編集」ボタンで既存データをモーダルに読み込む
- 保存は POST upsert（日付ベースで上書き）

### 4-3. テキストコピー
- 「コピー」ボタンで以下フォーマットをクリップボードに出力

```
【日付】M/D
【名前】〇〇

■ 本日行った業務
...

■ 進行中のタスク
...

■ 行いたい業務（今後やること）
...

■ 引き継ぎ内容
...

■ 問題点・気づき / 改善案
...

■ 全体共有内容
...

■ 質問 / サポート依頼
...
```

- コピー完了後2秒間「コピー済み」表示

### 4-4. ページング
- 5件/ページ、日付の新しい順で表示

## 5. データ定義

### テーブル: `daily_reports`

| カラム | 型 | 説明 |
|---|---|---|
| id | SERIAL PK | 自動採番 |
| user_id | UUID FK → profiles | 作成者 |
| report_date | DATE | 日報対象日（user_id と UNIQUE） |
| tasks_done | TEXT | 本日行った業務 |
| tasks_ongoing | TEXT | 進行中のタスク |
| tasks_planned | TEXT | 行いたい業務 |
| handover | TEXT | 引き継ぎ内容 |
| issues | TEXT | 問題点・気づき |
| sharing | TEXT | 全体共有内容 |
| questions | TEXT | 質問・サポート依頼 |
| created_at | TIMESTAMPTZ | 作成日時 |
| updated_at | TIMESTAMPTZ | 更新日時 |

**制約:** `UNIQUE(user_id, report_date)` — 1ユーザー1日1件

---

## 6. API定義

| メソッド | エンドポイント | 説明 |
|---|---|---|
| GET | `/api/daily-reports` | 自分の日報一覧（日付降順） |
| GET | `/api/daily-reports?date=YYYY-MM-DD` | 特定日の日報取得 |
| POST | `/api/daily-reports` | 作成 / 上書き（upsert） |
| DELETE | `/api/daily-reports/[id]` | 特定日報の削除 |

**認証:** 全エンドポイントでSupabase Auth セッション必須、未認証は401

---

## 7. 権限・セキュリティ

| ポリシー | 内容 |
|---|---|
| SELECT | 自分の日報のみ参照可能（`auth.uid() = user_id`） |
| INSERT | 自分のuser_idでのみ登録可 |
| UPDATE | 自分の日報のみ更新可 |
| DELETE | 自分の日報のみ削除可 |

→ RLSで全操作を制限。APIルートでも二重チェック。

## 9. 現在のプロトタイプの課題・未実装

| # | 課題 | 優先度 |
|---|---|---|
| 1 | 名前がハードコード（`'河野'`固定） → ログインユーザー名から自動取得すべき | 高 |
| 2 | 削除ボタンがUI上に存在しない（APIはある） | 中 |
| 3 | 管理者が全員の日報を閲覧できる画面がない | 中 |
| 4 | `updated_at` が自動更新されない（トリガー未設定） | 中 |
| 5 | 日報一覧に表示されるのは業務・進行・気づきの3項目のみ（引き継ぎ等は非表示） | 低 |

## 10. 今後の拡張案（優先度順）
